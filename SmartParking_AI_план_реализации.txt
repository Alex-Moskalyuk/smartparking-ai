SMARTPARKING AI
Подробный план реализации ML-проекта и защиты перед инвестором
==========================================================

1. КОНЦЕПЦИЯ ПРОЕКТА
------------------
Название: SmartParking AI.

Идея: программная система автоматического распознавания автомобильных номеров с камер парковок. Система определяет номер машины, сверяет его с базой разрешённых автомобилей и выдаёт решение: разрешить въезд, отказать или передать на ручную проверку.

Целевая аудитория:
- Небольшие платные парковки.
- Жилые комплексы и бизнес-центры.
- Офисные здания и предприятия.
- Логистические объекты с контролем въезда.

Проблема клиента:
- Ручной контроль пропусков требует времени и ресурсов.
- Физические пропуска теряются и создают расходы на обслуживание.
- Обычные камеры записывают видео, но не автоматизируют процессы въезда и учёта.

Предполагаемое преимущество: доступная автоматизация на существующих камерах с возможностью локальной обработки кадров. Это бизнес-гипотеза, которую нужно проверить сравнением с конкурентами.

Результат учебного проекта: обученные модели + измеримые ML-эксперименты + работающее MVP + бизнес-модель + демонстрация перед преподавателем-инвестором.

Ориентировочные сроки: 4–6 недель.
Команда: 3–5 человек.
Основной язык: Python.

4. ДАТАСЕТЫ
------------
Основные источники:

1) Car Plate Detection Dataset — фотографии с разметкой для детекции российских номеров.
   https://huggingface.co/datasets/AY000554/Car_plate_detecting_dataset

2) Car Plate OCR Dataset — изображения номерных знаков и соответствующие текстовые метки.
   https://huggingface.co/datasets/AY000554/Car_plate_OCR_dataset

Дополнительные источники для тестов и сравнения:

3) UFPR-ALPR — автомобильные номера в условиях съёмки с камер.
   https://github.com/raysonlaroca/ufpr-alpr-dataset

4) CCPD — крупный датасет китайских номеров; полезен для экспериментов с детекцией и устойчивостью, но не как прямой основной источник для российского OCR.
   https://github.com/detectRecog/CCPD

Перед использованием проверить актуальные правила загрузки, лицензии данных и допустимые способы публикации изображений. Для демонстрационного видео использовать собственные материалы с разрешением или подходящие открытые записи.

Принципы подготовки:
- Разделить данные на train / validation / test (например, 70% / 15% / 15%).
- Исключить попадание почти идентичных кадров одной машины в разные выборки.
- Проверить изображения, метки, повреждённые файлы и повторы.
- По возможности отделить собственный тестовый набор: 100–300 кадров, снятых в условиях предполагаемого применения.
- Не подбирать гиперпараметры по финальной test-выборке.

6. МЕТРИКИ И ЭКСПЕРИМЕНТЫ
------------------------
Детекция номера:
- Precision: сколько найденных номеров действительно являются номерами.
- Recall: сколько существующих номеров модель нашла.
- mAP@50: качество обнаружения при IoU 0.5.
- mAP@50–95: оценка по нескольким порогам IoU.
- Latency: время обработки одного кадра.

Распознавание текста:
- Character Accuracy: доля правильно распознанных символов.
- CER: Character Error Rate.
- Exact Match Accuracy: доля полностью правильно распознанных номерных строк.

Проверка бизнес-сценария:
- Доля верных решений о разрешении/запрете доступа.
- Доля ложных разрешений (особо важная ошибка для контроля доступа).
- Доля случаев, отправленных на ручную проверку.
- Задержка от появления автомобиля до решения системы.

Матрица экспериментов:
1) YOLO без аугментаций vs YOLO с аугментациями.
2) YOLO11n vs YOLO11s.
3) 640 px vs 960 px на входе детектора.
4) PaddleOCR vs самостоятельно обученная CRNN.
5) Один кадр vs агрегирование нескольких кадров.

Для каждого эксперимента зафиксировать: гипотезу, данные, параметры, метрики, результат, интерпретацию. Итоговые цифры вносить только после реального запуска.

В качестве ориентиров учебного MVP можно стремиться к mAP@50 >= 0.90 и высокому Exact Match на качественных дневных кадрах. Эти значения не являются обещанием: итог зависит от данных и оборудования.


7. ПРИМЕР ОБУЧЕНИЯ YOLO
------------------------
После подготовки конфигурации configs/plates.yaml:

    from ultralytics import YOLO

    model = YOLO("yolo11n.pt")
    model.train(
        data="configs/plates.yaml",
        epochs=50,
        imgsz=640,
        batch=16,
        patience=10,
        seed=42,
        project="runs/detector",
        name="yolo11n_baseline"
    )
    metrics = model.val(data="configs/plates.yaml", split="test")
    print(metrics.results_dict)

Пример configs/plates.yaml:

    path: data/processed/detection
    train: train/images
    val: val/images
    test: test/images
    nc: 1
    names:
      0: license_plate

В каталогах train/val/test должны быть соответствующие images и labels. При нехватке видеопамяти уменьшить batch. Для обучения желательно использовать GPU.


8. ПРОВЕРКА ФОРМАТА НОМЕРА
--------------------------
Пример для распространённого формата российских легковых номеров:

    import re

    PLATE_PATTERN = re.compile(
        r"^[ABEKMHOPCTYX]\d{3}[ABEKMHOPCTYX]{2}\d{2,3}$"
    )

    def valid_plate(text):
        return bool(PLATE_PATTERN.fullmatch(text))

Перед проверкой необходимо нормализовать распознанные буквы (например, привести схожие кириллические и латинские символы к общему алфавиту). Этот шаблон не охватывает все типы российских номеров.

Не следует автоматически открывать доступ на основании единственного предсказания с низкой уверенностью. Для сомнительных случаев нужен ручной контроль.

12. БИЗНЕС-МОДЕЛЬ
-----------------
Основной вариант: B2B-подписка за подключённую камеру/объект, плюс отдельная оплата внедрения или поддержки.

Клиенты: парковки ЖК, бизнес-центров, небольших предприятий.

Что продаём: не «нейросеть», а экономию времени и автоматизацию контроля доступа.

Гипотетический пример (не рыночный прогноз):
- 20 объектов.
- В среднем 2 камеры на объект.
- Подписка 3 000 рублей за камеру в месяц.
- Выручка: 20 x 2 x 3 000 = 120 000 рублей в месяц.
- Годовая выручка: 1 440 000 рублей.

Необходимо отдельно оценить расходы: установка, сервер/мини-ПК, поддержка, разработка, продажи, налоги, обслуживание и возможная стоимость коммерческих лицензий. Выручка не равна прибыли.

Что исследовать для питча:
- Минимум 3 конкурента: цена, функции, локальная работа, интеграции.
- Что дорого или неудобно для маленького клиента в существующих решениях.
- Стоимость пилота и ожидаемый срок окупаемости для заказчика.
- Как найти первых 5–10 клиентов и подтвердить готовность платить.

Конкурентное преимущество нужно доказывать, а не просто заявлять.

15. РИСКИ И ПЛАН Б
------------------
