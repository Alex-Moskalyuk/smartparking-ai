# Часть 3. Чтение номера

Этот файл объясняет, что делать. Код пишется в `notebooks/03_ocr.ipynb`: на каждый шаг своя ячейка.

Часть 3 получает уже вырезанный номер и возвращает текст. Искать табличку на всей фотографии не нужно: рамку находит часть 2, сюда приходит кроп.

## С чего начать

Фотографий в git нет. Из корня репозитория один раз:

```powershell
python src/prepare_data.py
pip install -r requirements-ocr.txt
```

Первая команда скачивает около 7 ГБ и собирает CSV. Вторая ставит PyTorch из общего списка и PaddleOCR для базового прогона. Если `paddlepaddle` не ставится на вашу версию Python, поставьте CPU-сборку со страницы Paddle под свою версию, затем снова `pip install paddleocr`. Ячейки своей CRNN от этого не зависят: их можно писать и обучать без Paddle.

Ноутбук открывать из корня репозитория.

## Какие файлы брать

| Файл | Зачем |
|---|---|
| `data/processed/ocr/train.csv` | обучение CRNN |
| `data/processed/ocr/val.csv` | выбор модели и разбор ошибок |
| `data/processed/ocr/test.csv` | один финальный прогон, не для подбора |

Колонки: `split`, `image`, `text`, `width`, `height`, `valid_format`. Текст уже в латинице, без пробелов. Алфавит: `0123456789ABEKMHOPCTYX`. Кропы горизонтальные, медиана около 238×51. Поворачивать их не нужно.

На этой части около 37 778 кадров в train, 4 890 в val и 2 841 в test. Если CSV нет или `train.csv` пустой, часть 1 запускали с `--quick`. Нужен полный `python src/prepare_data.py`.

## Что сравниваем

Две модели, не больше.

1. PaddleOCR без своего обучения. Это база: она должна заработать раньше CRNN.
2. Своя CRNN: свёртки, затем двунаправленная LSTM, затем линейный слой и CTC. Это обязательный свой эксперимент.

Другие OCR-сети не добавлять. Если CRNN не успевает, рабочим распознавателем для части 4 остаётся PaddleOCR, а в таблице у CRNN пишется, что обучение не закончено.

Test не использовать, пока модель не выбрана по val.

## Решения, которые не надо заново придумывать

Вход CRNN: серое изображение, пропорции сохранить, дополнить до 32×160. Оптимизатор AdamW, learning rate около 0.001, batch 32, если влезает в память, иначе меньше. Эпох закладывать 20–40, останавливаться раньше, если val CER не улучшается. Сохранять лучший вес, не последний. Функция потерь — CTC, в алфавите есть отдельный blank.

Метрики на val, одни и те же для обеих моделей:

- CER, доля лишних, пропущенных и заменённых символов;
- точность символов;
- Exact Match, доля номеров, совпавших целиком.

Менять между PaddleOCR и CRNN только модель. Данные, split и метрики те же.

## Порядок ячеек

Пропущенную ячейку не удалять. Если шаг не делался, в ней пишется причина.

1. Проверить, что CSV на месте и картинки по путям открываются.
2. Посмотреть несколько кропов и сверить картинку с колонкой `text`.
3. Прогнать PaddleOCR по val и посчитать три метрики.
4. Собрать загрузчик CRNN: серый кроп, пропорции, padding до 32×160, кодировка алфавита.
5. Описать модель CNN, BiLSTM, линейный слой.
6. Обучить с CTC, ранней остановкой и сохранением лучшего веса по val CER.
7. Посчитать те же три метрики для CRNN на val.
8. Собрать таблицу PaddleOCR против CRNN.
9. Разобрать ошибки на val: пары 0/O и 8/B, тёмные и размытые кропы. Сохранить примеры.
10. Один раз посчитать test у модели, которую забирает часть 4. По test модель не выбирать.
11. Записать, какой вес или какой вызов PaddleOCR переходит в часть 4 и почему.

## Когда часть закрыта

- PaddleOCR посчитан на val. CRNN либо посчитана на val, либо в ячейке обучения написано, почему её нет.
- В таблице три метрики и одна фраза, кто лучше на val.
- Есть примеры ошибок, не только средние числа.
- Test посчитан один раз у выбранной модели.
- Часть 4 может прочитать кроп и получить строку, не готовя датасет заново.
